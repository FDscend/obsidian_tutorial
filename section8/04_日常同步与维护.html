5. 故障排查指南

5.1 网站不更新

  1. 检查 Actions 页面 是否有失败
  2. 确认 main 已推送到远程（git push）
  3. 确认 sync-main-to-v5 成功触发
  4. 确认 deploy 成功触发
  5. 硬刷新浏览器（Ctrl+F5）

5.2 受保护分支导致同步或部署失败

当 main、v5、gh-pages 都要求通过 PR 更新时，管理员仍可让工作流自动维护 v5 与 gh-pages：

  • ruleset 的 Bypass list：仅为 Repository admin 选择 Always allow；不要为普通协作者添加 Write 或 Maintain bypass；
  • 仓库 secret：使用管理员账号创建的 Classic PAT（repo scope），名称为 PERSONAL_TOKEN；
  • 同步工作流：两个 checkout 均使用 persist-credentials: false，再以 PAT 推送 v5；
  • 部署工作流：监听 v5 推送，并将 PAT 传给 peaceiris/actions-gh-pages 推送 gh-pages。

这使成员仍只能通过 PR 修改受保护分支；只有管理员本人及由其 PAT 认证的自动化流程能够直推机器维护分支。

如果日志出现 GH013: Changes must be made through a pull request，不要先删除 PR 规则。优先查看日志提供的 ruleset 链接，并检查 checkout 是否意外保留了 GITHUB_TOKEN。详见 03_自动化部署流水线 的排查步骤。

5.4 图片不显示

  1. 确认图片文件已 git add 到 main 分支
  2. 确认引用路径正确（如 ../image/xxx.png）

5.5 链接 404

Quartz v5 自动处理 wikilink 转换。如果手动编写的链接出现 404：

  • 使用相对路径：../sectionX/文件名.md
  • 文件名区分大小写
  • 特殊字符会被 URL 编码

常见问题

Q: 推送到 main 后网站没有更新？

去 Actions 页面查看工作流是否正在运行。如果 sync-main-to-v5 失败，查看日志中的具体错误。

Q: 新增了目录但同步没生效？

同步工作流的 for dir 列表需要手动更新。这是为了防止意外同步不需要的目录。

Q: npm ci 和 npm install 有什么区别？

npm ci 根据 package-lock.json 精确安装，速度更快。npm install 会更新 lockfile。在 CI 环境中推荐 npm ci。
